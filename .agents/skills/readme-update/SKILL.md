# README update

1. Inspect the requested scope and current README. Resolve junctions before counting skills or agents. Read definitions for changed entries; inspect the full catalog only for a requested inventory audit.
2. Match descriptions to actual behavior and metadata. Prefer a link to the authoritative workflow over a duplicate sequence that can drift.
3. For new or changed author, license or copyright claims, verify the local license and original source. Preserve unchanged credits during behavior-only edits. If provenance cannot be established, report that specific gap and finish independent edits without inventing attribution.
4. Write the authorized update directly. Ask only for missing facts or a genuinely new decision, not routine confirmation already covered by the user's request.
5. Apply [unslop](../unslop/SKILL.md), then [humanizer](../humanizer/SKILL.md) to changed prose in the same agent. These are editing passes, not requests to spawn agents. Preserve code, license text, metadata and link targets.
6. Check local references and factual claims. Summarize the changes and remaining gaps. Follow workspace publication rules; README editing itself does not authorize a push or merge.

Keep the user's voice. Retain useful diagrams, but remove a duplicated workflow diagram when a short authoritative link explains it better. Add a new diagram only when requested or approved. Missing optional layout folders are not a reason to invent a new harness structure.
