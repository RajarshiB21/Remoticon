# Headless pi calls

This rule applies only when the task explicitly requires a headless pi invocation. It is not authorization to launch another model.

Before a call, verify the installed CLI's current options, the requested provider/model, authentication and cost. Do not assume a default provider, supported effort or billing arrangement from an old session. Live model calls require existing explicit authorization. Never use OpenRouter without the user's explicit spending approval.

Prefer an existing deterministic fixture when testing product behavior. A headless model response does not prove native fullscreen appearance or responsiveness.

For an authorized long-running call, use the available process tool's managed session and capture output to a task-owned file. Verify completion, exit status and owned-process cleanup. Redirection alone neither starts a background process nor guarantees that it cannot hang. Never print credentials or full inherited environment values.

Use the workspace's current workflow and agent allocation; headless pi is not an alternate route around review limits.
